# Backend: OpenSpec документации и ADR

## Цель
Завести документационный слой OpenSpec/ADR для backend-проекта.

## Контекст
Backend отвечает за FastAPI/OpenAPI API, оркестрацию задач и интеграции с провайдерами генерации.

## Что делаем
- Создать `docs/adr/` для архитектурных правил backend.
- Создать пустые `docs/adr/rules.md` и `docs/adr/agent.md`.
- Создать spec, фиксирующий документационную структуру backend.

## Что НЕ делаем
- Не добавлять backend-код сверх существующей заглушки.
- Не выбирать БД, очередь или провайдеров без отдельного ADR.
- Не смешивать frontend-решения с backend-правилами.

## Критерии приёмки
- В `backend/docs/` есть README, specs и adr.
- `backend/docs/adr/rules.md` и `backend/docs/adr/agent.md` существуют и пока пустые.
- Spec backend лежит в `backend/docs/specs/todo/`.

## Открытые вопросы
- Какие архитектурные правила первыми занести в `rules.md`?
- Какие инструкции для агентов должны попасть в `agent.md` после выбора рабочих процессов?
